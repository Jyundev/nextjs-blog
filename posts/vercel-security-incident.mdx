Vercel 보안 사고 이후, 최근 프로덕션으로 배포한 앱의 Vercel 환경 변수를 점검했다.

## Vercel 2026년 4월 보안 사고 정리

### 1. 사건의 발단

시점: 2026년 4월 19일 처음 공개 (최종 업데이트 4월 24일).

공격 경로: Vercel 자체 시스템의 취약점이 아니라, Vercel 직원이 사용하던 **서드파티 AI 생산성 도구인 'Context.ai'** 가 해킹당하면서 시작되었다.

침입 방법

> 1. 해커가 Context.ai의 Google Workspace OAuth 앱 권한을 탈취했다.
> 2. 이를 통해 해당 앱을 사용하던 Vercel 직원의 기업용 Google 계정에 접근했다.
> 3. 탈취한 계정 권한을 이용해 Vercel 내부 시스템 및 일부 고객 데이터 환경에 무단 침입했다.

### 2. 피해 규모 및 범위

- 주요 타겟: Vercel에 저장된 환경 변수(Environment Variables).

- 노출 데이터: 'Sensitive'로 설정되지 않아 평문(Plaintext)으로 읽을 수 있던 API 키, DB 비밀번호, 토큰 등이 노출되었다.

- 영향을 받은 계정: Vercel은 "전체 고객 중 제한된 일부(Limited subset)"라고 밝혔으나, 일부 외신에서는 유출 데이터가 판매되고 있다는 정황을 보도하기도 했다.

- 안전한 영역: Vercel이 제공하는 'Sensitive' 옵션으로 암호화된 값들은 노출되지 않았다.

- 오픈소스 프레임워크: Next.js, Turbopack 등 Vercel이 관리하는 오픈소스 패키지에 대한 변조(Backdoor 등) 흔적은 발견되지 않았다.

### 3. Vercel의 대응과 권고

즉각 조치: 외부 보안 업체(Mandiant)와 협력하여 침입 경로를 차단하고, 영향을 받은 사용자들에게 이메일로 개별 통보했다.

사용자 권고 사항

- Secrets Rotation: Vercel에 등록된 모든 API 키와 비밀번호를 즉시 교체할 것.
- Sensitive 설정 생활화: 앞으로 모든 민감 정보는 반드시 'Sensitive' 옵션을 켜서 저장할 것.
- 보안 강화: 2단계 인증(MFA) 설정 및 대시보드 활동 로그 확인.

이번 이슈에 대한 자세한 내용은 [Vercel 공식 Security Bulletin](https://vercel.com/kb/bulletin/vercel-april-2026-security-incident)에서 확인할 수 있다.

## 내 프로덕션 앱에 미친 영향

내 앱은 다음 구조였다.

- Next.js (Vercel)
- Supabase
- Resend

즉 환경 변수 관리가 매우 중요했다.

배포 플랫폼의 env가 노출되면 애플리케이션 전체 권한으로 이어질 수 있다.

공개 키 외에도, 민감 정보를 포함한 자동 생성 환경변수들이 함께 등록되어 있었다.
또한 실제로 사용하지 않는 Supabase 관련 고위험 env 값들도 남아 있었다.
이는 Vercel 프로젝트 생성 과정에서 Supabase Integration을 연결하며 자동으로 추가된 값들로 보였다.

## 실제 수행한 보안 개선

### 1. 메일 키 교체

- `RESEND_API_KEY` 재발급

### 2. Supabase 키 체계 최신화

Legacy `anon`, `service_role` API key를 Supabase가 애플리케이션 요구 사항을 더 잘 지원하기 위해 업데이트한 API로 교체했다.

기존:

- anon key
- service_role key

변경:

- publishable key
- secret API key

레거시 키는 바로 비활성화하지 않았다. 외부 Integration이나 숨은 의존성이 있을 수 있어,
새 키 전환 후 충분한 테스트를 거쳐 단계적으로 제거하기로 했다.

### 3. 미사용 Secret 제거

자동 생성되었지만 사용하지 않던 다음 값들을 삭제했다.

- `POSTGRES_PASSWORD`
- `DB_URL`
- JWT 관련 값
- 중복 공개 키

### 4. 운영 테스트

보안 변경 이후 핵심 기능이 정상 동작하는지 확인했다.

- 로그인
- CRUD
- 메일 발송
- 세션 유지

모두 정상 확인했다.

## 느낀 점

기능 개발만 하던 시기에는 환경 변수는 넣어두면 끝이라고 생각했다. 배포 플랫폼을 사용하면 보안까지 자동으로 해결된다고 착각하고 있었다. "알아서 잘 해주겠지"라는 위험한 생각을 했던 것이다.

개인 프로젝트일 때는 다소 안일하게 접근하더라도 크게 문제가 되지 않을 수 있다. 하지만 프로덕션으로 배포한 이후에는 보안 요소들을 점검하고, 사용하고 있는 Vercel이나 Supabase의 이슈 사항도 꾸준히 확인해야 한다는 사실을 다시 한번 깨달았다.

작은 앱이어도 프로덕션은 프로덕션이다. 이번 대응은 단순 키 교체가 아니라 운영자로서 보안 감각을 다시 점검한 계기였다.
